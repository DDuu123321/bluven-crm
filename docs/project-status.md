## 1. 现在在哪一步

**开发已经完成，还没有上线。**

从线索进入到尾款到账、关闭工单，整条流程都已做好，并有自动化测试覆盖。接下来是部署、接通真实服务，再和员工一起验收。

## 2. 已完成的部分

| 部分 | 内容 |
|---|---|
| 线索 | 从网站后台自动取线索、接收接口、CSV 导入、手动录入；按电话、邮箱认人，再按地址判断是否重复；主管分派；闲置提醒，超期自动回到主管的未分派池 |
| 销售 | 开工并选线索来源；电话、备注、待办和时间线；文件夹和资料上传，推送前的资料夹（The folder）；报价版本和签字版；定金和凭证；推送运营 |
| 运营 | 接收订单并确认定金；工单六项；补传资料和备注；通知客户日期；完工；补贴和尾款提醒；请销售催尾款；确认尾款并关闭工单；特殊情况退回销售；做不下去时取消订单并记录退款状态 |
| 财务 | Payments 页：Deposits（定金）、Balances due（应收尾款）、Final payments received（已到账尾款）、Refunds to pay（待退款）；定金和尾款到账时收到通知 |
| 客户邮件 | 每位销售连接自己的 Zoho 邮箱，在 CRM 里收发邮件，附件存进订单资料；三封自动发给客户的邮件及其模板 |
| Pylon | 从订单点 Design in Pylon，带着订单号在 Pylon 建项目，或关联已有项目；读取设计、报价版本和签字文件；每分钟读取 Pylon 的事件，可另加 webhook；网关付款自动生成定金记录 |
| AI 助手 | 订单总结、信息抽取、附件识别、账单读取、回信草稿、交接简报；自动任务 24 小时内最多 300 次，其中每张订单最多 25 次；按按钮的请求每人每小时最多 60 次 |
| 管理 | 用户和角色、各项设置、站内通知和每日摘要邮件、仪表盘和订单导出、资料保留、操作日志 |
| 部署 | Docker 镜像、Docker Compose（含 HTTPS 和备份脚本）、Railway 的部署步骤 |

## 6. 待负责人确认

和负责人的说法不一致，需要确认的：

1. **客户明确拒绝的订单。** 负责人的笔记写的是关闭并删除文件夹和订单。系统现在是关闭不删除，按丢单处理，订单和资料留档，资料到保留期后再清理。
2. **方案发出后的状态。** 负责人的笔记写的是仍为跟进。系统单独显示为"方案已发"，做法和跟进一样。
3. **方案里的条款。** 会上负责人说，正常要把整份方案连同条款（T&Cs）发给客户，这是 NETCC 的要求；只有还在犹豫、或可能是同行的客户，才只发报价。流程说明现在写的是"通常只保留报价部分"，要按负责人的说法改。
4. **Xero。** 会上说定金到账后，CRM 要在 Xero 生成整单金额的发票，发票不发给客户。系统还没做，生成的时点也没定。

等 D 哥或负责人定的：

- 运营的六项保留哪几项，尤其要不要记备货状态。现在六项都做了。
- 通知客户安装日期和到货的邮件什么时候发。现在是运营点按钮发。

已给出初始值、可在 Administration 里修改的设置：线索来源七项；丢单原因十项；交接清单（Handoff checklist）里的三类必备资料（电费账单、安装位置照片、电表箱照片）；定金建议比例 10%；闲置 5 / 8 / 10 天，分别提醒销售、提醒主管、回到主管的未分派池；补贴提醒 2 个工作日；请客户在 5 个工作日内付尾款，到期没关单就提醒运营；资料保留 2 年，提前 30 天提醒；三封客户邮件的英文模板。三封邮件的措辞请负责人过目。资料到期后要不要自动删除，默认不删，也请负责人定。

还没定的：

- 网站接口要不要补上月电费、购买时间、备注等询价信息，由网站一侧决定，写法见对接说明 A.4。
- 完工后申请补贴所需的安装方证件，会上提到，暂不处理。
